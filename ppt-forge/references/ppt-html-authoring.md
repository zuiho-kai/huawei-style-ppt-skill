# PPT 制作参考 — 华为式 HTML 可编辑 Deck(数据密集型技术汇报)

> ppt-forge 的**可编辑 HTML 轨道**,与 imagegen raster 轨道互补。
> 适用场景:工程/技术领导受众、内容需要**逐字准确且可反复改稿**、需要嵌入**真实数据表与架构图**、
> 最终要导出为 PPTX/PDF 的数据密集型汇报。
> 视觉规范一律沿用 [华为式专业汇报 preset](ppt-style-huawei.md);本文只补充 HTML 轨道特有的制作流程与版式模式。

---

## 一、何时用 HTML 轨道,而不是 imagegen

| 维度 | imagegen raster 轨道 | HTML 可编辑轨道(本文) |
|---|---|---|
| 文字准确性 | 需生成后逐字核对,易出伪字 | 直接写死,零伪字 |
| 改稿成本 | 重新出图 | 就地改文本/数字 |
| 数据表、公式、代码标识 | 易错、不可选中 | 精确、可选中 |
| 架构/数据流图 | 概念图,不精确 | 原生 SVG,坐标可控、可导出 |
| 导出 PPTX | 整页 PNG | 原生文本框/形状(见交接协议) |
| 视觉自由度 | 高(氛围图、渲染) | 中(规整版式) |

**判据**:一页的价值在于"精确的字与数"(基准表、指标定义、架构、对比)→ 用 HTML 轨道;
一页的价值在于"氛围与概念"(封面、愿景、产品渲染)→ 用 imagegen 轨道。一套 deck 可混用,但底部总结条、配色、字体必须跨页一致。

---

## 二、页面骨架(固化)

- **画布**:16:9,授权尺寸 **1920×1080**;每页一个 `section`,由 deck 外壳负责缩放/翻页/缩略图/导出。
- **中文字体**:微软雅黑(Microsoft YaHei);英文/数字 Arial。在 `<helmet>` 里声明一次 `font-family`,不逐元素重复设别的字体。
- **字号地板(硬规则)**:大屏汇报**任何可读文字 ≥ 16px(授权尺寸)**。注释来源可到 14–16px,但正文、标签、表格、图内文字都不得低于 16px。内容放不下时**精简/重组/拆页**,不缩字硬塞。
- **三区结构**(沿用 preset §六):
  1. 标题区:左上,红色 eyebrow(字母间距大写)+ 结论式主标题 + 品牌红细线;右上放页码(浅灰大号)+ 页名。
  2. 内容区:卡片/表格/流程/图,3–6 个信息组。
  3. 底部:总结条 + 灰色斜体来源行。
- **卡片**:白底 `#FFFFFF`,边框 `#DDDDDD`,**直角**;分区标题红色 `#C7000B`(或目标品牌红)。

---

## 三、底部总结条(两种做法,择一并全套统一)

华为标志性的"红底白字总结条"是默认做法;数据密集页上,**透明底 + 红框 + 红字**同样地道,且不与页面上的红色强调抢视觉。**一套 deck 只用一种**。

```html
<!-- A. 实心红底白字(强收束) -->
<div style="background:#C7000B;color:#fff;font-size:22px;font-weight:700;padding:13px 22px;line-height:1.3;">一句话结论</div>

<!-- B. 透明底 + 2px 红框 + 红字(克制,推荐用于图/表密集页) -->
<div style="background:transparent;color:#C7000B;border:2px solid #C7000B;font-size:22px;font-weight:700;padding:12px 20px;line-height:1.3;">一句话结论</div>

<!-- 紧随其后:灰色斜体来源行 -->
<div style="font-size:16px;font-style:italic;color:#898989;margin-top:7px;">数据来源:…,2026-07</div>
```

要点:总结条是**一句话结论**(不是要点罗列),长度控制在单行不换行;做完后并排检查三页,确保颜色/边框/字号一致。

---

## 四、N 栏对比页(VS 页的扩展)

preset §七.6 的 VS 页是两栏;技术汇报常需要**三栏对比**(如:方案 A / 方案 B / 评测)。规则:

- 每栏顶部:红色分区标题 + 一枚中性灰徽标(标注模型/版本/角色)。**同一语义维度的栏用同色标题**;若两栏属同一产品的不同模式,都用品牌红标题,用徽标区分。
- 栏间用 1px `#DDDDDD` 竖分隔 + `padding-left` 留白,不用 `gap` 造成边界含糊。
- 数字对比:**己方反超项标红加粗**,其余中性深灰;基线列恒中灰。
- 栏宽按内容密度分配(如 32% / 36% / 32%),图所在栏可略宽以保证图内文字 ≥16px。

---

## 五、嵌入架构 / 数据流图(关键)

技术汇报的图必须精确、可导出、可读。**用原生文字 SVG,不要 imagegen 概念图,也不要 `<foreignObject>`。**

- **画法**:`<rect>` 画 chip、`<text>` 写标签、`<line>`+`<marker>` 画箭头。全部 `<text>` native(不用 `foreignObject`),这样在 `<img>`、内联、PPTX 光栅、PDF 里都能渲染。
- **配色**:沿用 chip-and-box 约定 —— 边框 `#333`,分类芯片浅色填充(蓝 `#d1dae7` / 绿 `#c8d3c8` / 紫 `#dfd6e0` / 高亮 `#fffde7` / 中性白),灰底盒 `#E7E7E3`,箭头 `classic` 细箭头(盒内 `#666` / 跨区 `#333`),分区标题用 preset 的域色(蓝 `#1a5276` / 绿 `#2d7600` / 紫 `#7b1fa2` / 金 `#b8860b`)。竖排数据流:主脊居中,正交输入(数据通道/知识平面)作左右侧栏用横向箭头汇入,产物在底部扇出。(完整 chip/箭头/阴影规格见 draw.io 架构图 skill。)
- **字号换算(务必核算)**:SVG 以 `viewBox` 单位作图,按显示宽度缩放。授权渲染字号 = SVG native 字号 × (授权显示宽度 / viewBox 宽度)。**先量出该图在栏内的授权显示宽度**,反推 native 字号使**最小文字 ≥16px 授权**。窄栏里为保证 ≥16px,通常要**去掉小字副标题、只留主标签**,并让 `viewBox` 接近栏的宽高比(避免被高度限制而缩小)。
- **放置**:`<img src="diagram.svg" style="max-width:100%;max-height:100%;width:auto;height:auto">`,并加 `data-om-raster` 让 PPTX 导出按整图光栅嵌入。把 `.svg` 作为独立文件维护(易改、易复用),文件名用 ASCII。

## 六、评测 / 指标页

- **基准表**:按任务类型分组(如 PR 评审维度 / issue 应答维度),每组一个子表头;己方反超的维度标红加粗;附"胜负(己方/基线/平)"行与 replicate 说明。
- **指标定义页**:每个维度一张小卡(英文名 + 中文名 + 一句话释义);把"如何合并/排名"单列一条,写清是"逐维均值 + 头对头胜率"还是综合分。只有真实使用的公式才展示;不再使用的综合分要删掉,避免误导。
- **协议注**:净室/盲评等评测协议用一段灰色小字讲清(临时目录、双臂匿名、评审理由弃读、replicate 数、判官模型),让读者相信数字不是刷出来的。

---

## 七、数据接地纪律

- 所有规模/活跃度/效果数字必须来自**真实来源**(源码仓库统计、release notes、eval 结果、SPEC),在来源行注明。
- **不杜撰**任何数字;拿不到的指标就省略或标 `TBD`,不要为了"数据 slop"堆砌。
- 描述技术设计时以仓库实现为准,不凭记忆编造组件或结论。

---

## 八、验收门禁(HTML 轨道)

- 字号地板:全页(含 SVG 图内)授权字号 ≥16px —— 量一处已知授权字号的元素反推缩放比,核算图内最小字号。
- 无溢出:每个 `section` 的 `scrollHeight ≤ clientHeight`;栏内卡片不裁切文字。
- 跨页一致:标题区结构、总结条样式、配色、字体、页码位置三页统一。
- 红色克制:品牌红只用于结论、关键数字、分区标题、总结条,占比约 8%,不铺满。
- 逐字核对:数字、单位、来源、代码标识与原始材料一致。

---

## 九、常见错误(HTML 轨道)

| 错误 | 后果 | 修复 |
|---|---|---|
| 为塞下内容把字号压到 12–14px | 大屏读不清 | ≥16px 地板;超了就拆页/精简 |
| 架构图用 `foreignObject` 或 imagegen | `<img>`/PPTX 里空白或不精确 | 原生 `<text>` SVG,核算 native 字号 |
| 图挤进窄栏,字被缩到 <16px | 图不可读 | 去副标题留主标签,栏略加宽,viewBox 贴合栏比例 |
| 综合分/公式已不用却仍展示 | 误导受众 | 删掉;只留真实排名口径 |
| 数字无来源或凭记忆 | 不专业、不可信 | 源码仓库取数并注来源,拿不到标 TBD |
| 三栏用 `gap` 无分隔线 | 栏界含糊 | 1px `#DDDDDD` 竖线 + padding |
| 总结条两种样式混用 | 风格漂移 | 全套统一一种 |
